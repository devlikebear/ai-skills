# Product discovery

Begin at the first unresolved decision. Summarize the decisions already supplied
in a few sentences; do not restart a questionnaire when a usable brief exists.

## Concept

Describe a specific user in a specific situation, the problem and its current
workaround, and why the proposed product would improve that situation. If the
user is unsure, give two or three concrete alternatives and explain the scope
tradeoff. Separate reported evidence from assumptions and proposed experiments.
Do not invent market demand, usage data, or numerical success targets.

## MVP and acceptance

Choose one core journey from entry to useful outcome. For each candidate feature,
record the user outcome, necessity for that journey, dependency, and acceptance
scenario (starting state, action, expected visible result). Include failure,
empty, or recovery states where they could prevent the core outcome.

Prefer Now / Next / Later to numerical prioritization when evidence is sparse.
Explain what an excluded feature would add and why it can wait. Use scoring only
if it helps resolve a real tradeoff; avoid false precision in effort estimates.

Capture platform, available time, operating budget, data needs, accessibility,
and external integration constraints only when they affect the product choice.
Reuse the user's stack and deployment choices. If undecided, label a proposal
and its tradeoffs instead of presenting it as an established requirement.

## Optional UX

Describe screens, transitions, state, and feedback sufficient to validate the
core journey. Detailed visual mockups are a separate deliverable. Link UX
acceptance back to MVP items so a coding agent can test it.

## Output

Use [the product brief template](../templates/product-brief.md) for a requested
PRD or a substantial discovery result. For a small task, keep the brief inside
the development plan rather than generating redundant files. Record unresolved
choices, their impact, and which work can proceed independently.
